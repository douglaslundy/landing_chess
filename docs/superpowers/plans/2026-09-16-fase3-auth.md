# Fase 3 — Autenticação (admin + cliente) + log de acesso — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a full authentication mechanism for two independent profiles (admin and client) to the existing Next.js app in `web/`, backed by Postgres sessions, plus login/logout, a client-side magic-link flow with optional password, and an access-log for auditing — ending with minimal protected placeholder pages for both profiles running in production.

**Architecture:** Everything lives inside the existing `web/` Next.js App Router app, following its established conventions (no ORM, raw `pg` queries via `web/lib/db.js`, Zod validation, rate limiting via the existing `request_limits` table). Password hashing uses Node's built-in `scrypt` (no new dependency). Sessions are opaque tokens stored in a new `sessions` Postgres table, set as `httpOnly` cookies — one cookie name per profile (`admin_session` / `client_session`) so the two never collide in the same browser.

**Tech Stack:** Next.js 15 (App Router, Route Handlers, Server Components), `pg`, Zod, `node:crypto` (`scrypt`, `randomBytes`, `timingSafeEqual`), `vitest`.

**Spec:** `docs/superpowers/specs/2026-09-16-fase3-auth-design.md`

## Deviation from the spec's wording (read before starting)

The spec says protection is enforced by "`web/middleware.js`". This plan
implements the *same protection guarantee* — no protected page or API
route is reachable without a valid session — but via an explicit guard
call (`resolveSession`, Task 7) at the top of each protected route/page,
**not** a `web/middleware.js` file. Reason: Next.js Middleware runs on the
Edge runtime by default, which cannot open raw TCP sockets — `pg`
(Postgres) does not work there. Making middleware validate sessions
against Postgres would require the `nodeMiddleware` experimental flag,
which is unnecessary risk for a project this size. Route Handlers and
Server Components already run in the Node.js runtime by default (see
every existing route in `web/app/api/*`), so an explicit guard call there
is simpler, has zero runtime risk, and matches how this codebase already
does everything else (no shared middleware exists in the repo today).

Also: the spec describes `consumeMagicLink` as running "in the same
transaction" as marking the link used. This plan implements it as a
single atomic `UPDATE ... WHERE used_at IS NULL AND expires_at > now()
RETURNING email` statement instead (Task 5) — Postgres's row-level
locking on that single statement gives the same replay-safety without
needing an explicit transaction wrapper, and matches the atomic
single-statement style `web/lib/rate-limit.js` already uses.

## Global Constraints

- No new npm dependencies — hashing uses `node:crypto` only.
- All schema changes go in a new versioned migration file
  (`migrations/002_auth.sql`), never hand-edited on the VPS outside that
  file's content.
- Never persist a plaintext password or session token anywhere
  (`access_log.detail` must never contain one).
- Never edit the VPS root crontab — periodic cleanup piggybacks on the
  existing `web/app/api/cron/reconcile` route.
- Cookies: `httpOnly`, `secure` when `NODE_ENV === 'production'`,
  `sameSite: 'lax'`.
- Session TTL: 7 days (admin), 30 days (client). Magic link TTL: 30
  minutes, single use.
- Login rate limit: 5 attempts / 15 min per IP+email. Magic-link resend:
  1 / 2 min AND 5 / day per email (both must pass).
- Every new `web/lib/**` module gets a `web/tests/*.test.mjs` file in the
  same style as the existing suite (mock `pg` the way
  `web/tests/db.test.mjs` does — no real database in tests).
- Route Handlers (`route.js`) and pages (`page.js`) are **not** unit
  tested directly in this codebase (confirmed: no existing route.js is
  imported by any test) — their correctness is verified by the deploy
  task's end-to-end checklist (Task 18), matching how `orders`/`payments`
  routes were validated in Fase 2. Only `web/lib/**` gets unit tests.

```sql
  id uuid primary key,

  subject_id text,
```

```js
import { randomBytes, scrypt as scryptCallback, timingSafeEqual } from 'node:crypto';
import { promisify } from 'node:util';

const scrypt = promisify(scryptCallback);
const KEY_LENGTH = 64;

export async function hashPassword(plain) {
  const salt = randomBytes(16);
  const derivedKey = await scrypt(plain, salt, KEY_LENGTH);
  return `${salt.toString('hex')}:${derivedKey.toString('hex')}`;
}

export async function verifyPassword(plain, stored) {
  const [saltHex, keyHex] = String(stored).split(':');
  if (!saltHex || !keyHex) return false;
  const salt = Buffer.from(saltHex, 'hex');
  const storedKey = Buffer.from(keyHex, 'hex');
  if (storedKey.length !== KEY_LENGTH) return false;
  const derivedKey = await scrypt(plain, salt, KEY_LENGTH);
  return timingSafeEqual(derivedKey, storedKey);
}
```

```js
import { randomBytes } from 'node:crypto';
import { query } from '../db.js';

const TOKEN_BYTES = 32;

export async function createSession(subjectType, subjectId, ttlSeconds) {
  const token = randomBytes(TOKEN_BYTES).toString('base64url');
  await query(
    `insert into sessions (token, subject_type, subject_id, expires_at)
     values ($1, $2, $3, now() + ($4::int * interval '1 second'))`,
    [token, subjectType, subjectId, ttlSeconds]
  );
  return { token };
}

export async function getSession(token) {
  if (!token) return null;
  const result = await query(
    `select token, subject_type, subject_id, expires_at
     from sessions
     where token = $1 and expires_at > now()`,
    [token]
  );
  return result.rows[0] || null;
}

export async function destroySession(token) {
  if (!token) return;
  await query('delete from sessions where token = $1', [token]);
}

export async function cleanupExpiredSessions() {
  const result = await query('delete from sessions where expires_at <= now()');
  return result.rowCount;
}
```

```js
export const ADMIN_COOKIE = 'admin_session';
export const CLIENT_COOKIE = 'client_session';

function baseOptions() {
  return {
    httpOnly: true,
    secure: process.env.NODE_ENV === 'production',
    sameSite: 'lax',
    path: '/'
  };
}

export function setSessionCookie(response, name, token, maxAgeSeconds) {
  response.cookies.set(name, token, { ...baseOptions(), maxAge: maxAgeSeconds });
  return response;
}

export function clearSessionCookie(response, name) {
  response.cookies.set(name, '', { ...baseOptions(), maxAge: 0 });
  return response;
}
```

```js
import { randomBytes } from 'node:crypto';
import { query } from '../db.js';

const TOKEN_BYTES = 32;

export async function createMagicLink(email, ttlSeconds) {
  const token = randomBytes(TOKEN_BYTES).toString('base64url');
  const normalizedEmail = email.trim().toLowerCase();
  await query(
    `insert into magic_links (token, email, expires_at)
     values ($1, $2, now() + ($3::int * interval '1 second'))`,
    [token, normalizedEmail, ttlSeconds]
  );
  return token;
}

export async function consumeMagicLink(token) {
  if (!token) return null;
  const result = await query(
    `update magic_links
     set used_at = now()
     where token = $1
       and used_at is null
       and expires_at > now()
     returning email`,
    [token]
  );
  return result.rows[0] || null;
}
```

```js
import { NextResponse } from 'next/server';
import { query } from '../../../../lib/db.js';
import { getClientIp } from '../../../../lib/http.js';
import { rateLimit } from '../../../../lib/rate-limit.js';
import { adminLoginSchema } from '../../../../lib/schemas.js';
import { verifyPassword } from '../../../../lib/auth/password.js';
import { createSession } from '../../../../lib/auth/session.js';
import { setSessionCookie, ADMIN_COOKIE } from '../../../../lib/auth/cookies.js';
import { logAccess } from '../../../../lib/auth/accessLog.js';
import { SESSION_TTL_SECONDS } from '../../../../lib/constants.js';

export async function POST(request) {
  const ip = getClientIp(request);
  try {
    let raw;
    try { raw = await request.json(); } catch { raw = {}; }
    const { email, password } = adminLoginSchema.parse(raw);
    const normalizedEmail = email.toLowerCase();

    const allowed = await rateLimit({ key: `admin-login:${ip}:${normalizedEmail}`, limit: 5, windowSeconds: 900 });
    if (!allowed) return NextResponse.json({ error: 'rate_limited' }, { status: 429 });

    const result = await query('select id, password_hash from admin_users where email = $1', [normalizedEmail]);
    const admin = result.rows[0];
    const valid = admin ? await verifyPassword(password, admin.password_hash) : false;
    if (!valid) {
      await logAccess({ subjectType: 'admin', subjectId: null, event: 'login_failure', detail: 'invalid_credentials', ip });
      return NextResponse.json({ error: 'invalid_credentials' }, { status: 401 });
    }

    const { token } = await createSession('admin', admin.id, SESSION_TTL_SECONDS.admin);
    await logAccess({ subjectType: 'admin', subjectId: admin.id, event: 'login_success', ip });

    const response = NextResponse.json({ ok: true });
    return setSessionCookie(response, ADMIN_COOKIE, token, SESSION_TTL_SECONDS.admin);
  } catch (error) {
    if (error.name === 'ZodError') {
      return NextResponse.json({ error: 'invalid_input' }, { status: 400 });
    }
    console.error('[api/admin/login POST] failed:', error);
    return NextResponse.json({ error: 'server_error' }, { status: 500 });
  }
}
```

```jsx
  const [error, setError] = useState(null);

  async function handleMagicLink(event) {
    event.preventDefault();
    setError(null);
    setMessage(null);
    const response = await fetch('/api/client/magic-link/request', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ email })
    });
    const body = await response.json().catch(() => ({}));
    setMessage(body.message || 'Se este e-mail tiver uma compra confirmada, enviamos um link de acesso.');
  }

  async function handlePasswordLogin(event) {
    event.preventDefault();
    setError(null);
    setMessage(null);
    const response = await fetch('/api/client/login', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ email, password })
    });
    if (!response.ok) {
      setError('E-mail ou senha inválidos.');
      return;
    }
    window.location.href = '/cliente';
  }

  return (
    <main style={{ padding: 32, fontFamily: 'sans-serif', maxWidth: 360 }}>
      <h1>Entrar</h1>
      <label>
        E-mail
        <input type="email" value={email} onChange={(e) => setEmail(e.target.value)} required />
      </label>

      <form onSubmit={handleMagicLink}>
        <button type="submit">Receber link por e-mail</button>
      </form>
      {message && <p>{message}</p>}

      <form onSubmit={handlePasswordLogin}>
        <label>
          Senha (se você já criou uma)
          <input type="password" value={password} onChange={(e) => setPassword(e.target.value)} />
        </label>
        {error && <p role="alert">{error}</p>}
        <button type="submit">Entrar com senha</button>
      </form>
    </main>
  );
}
```

### Task 17: `scripts/create-admin.mjs` — admin seed helper

**Files:**
- Create: `scripts/create-admin.mjs`
- Test: `web/tests/create-admin.test.mjs`

**Interfaces:**
- Consumes: `hashPassword` (`web/lib/auth/password.js`) — no database
  connection needed (see rationale below).
- Produces: `buildInsertSql(email: string, passwordHash: string): string`
  (exported for testing) and a CLI entrypoint that prints ready-to-run
  SQL.

Rationale: the `admin_users` table lives in the VPS's Postgres, which is
only reachable from inside the Docker network — not from a developer's
machine, and the production `app` container image doesn't include
`scripts/` (see the Dockerfile's `runner` stage, which only copies
`.next/standalone`, `.next/static`, and `public/`). Rather than build
new network/deploy plumbing just to seed one row, this script computes
the password hash locally (pure `node:crypto`, no I/O) and prints a
finished `INSERT ... ON CONFLICT` statement. Task 18 pipes that output
through the exact same `ssh ... docker exec xadrez-postgres psql`
mechanism Fase 2 already used to apply `001_init.sql` — no new
deployment mechanism, and the plaintext password never leaves the local
machine.

```js
import { randomUUID } from 'node:crypto';
import { hashPassword } from '../web/lib/auth/password.js';

function sqlEscape(value) {
  return value.replace(/'/g, "''");
}

export function buildInsertSql(email, passwordHash) {
  const id = randomUUID();
  const escapedEmail = sqlEscape(email.trim().toLowerCase());
  const escapedHash = sqlEscape(passwordHash);
  return `insert into admin_users (id, email, password_hash) values ('${id}', '${escapedEmail}', '${escapedHash}') on conflict (email) do update set password_hash = excluded.password_hash;`;
}

async function main() {
  const [, , email, password] = process.argv;
  if (!email || !password) {
    console.error('uso: node scripts/create-admin.mjs <email> <senha>');
    process.exit(1);
  }
  const passwordHash = await hashPassword(password);
  console.log(buildInsertSql(email, passwordHash));
}

if (import.meta.url === `file://${process.argv[1]}`) {
  main();
}
```
